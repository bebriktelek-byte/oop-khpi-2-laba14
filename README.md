Ось структурований і технічно точний README.md для твоєї лабораторної або практичної роботи з багатопотоковості в Java. Оформив українською мовою з детальним описом взаємодії потоків.Document Workflow & Multithreading SystemКонсольний Java-додаток, що моделює систему автоматизованого документообігу компанії. Проєкт демонструє роботу з багатопотоковістю в Java (Multithreading), зокрема створення потоків різними способами, синхронізацію їх виконання за допомогою методу join() та симуляцію затримок часу (Thread.sleep()).  🛠️ Функціонал та логіка роботи системиДодаток реалізує паралельний двохетапний процес обробки документів:  Етап 1: Паралельна верифікація (Клас DocumentVerificationThread)Створюються окремі потоки обробки (спадкоємці класу Thread) для кожного документа.  Верифікація контенту виконується паралельно: перевіряється, чи текст документа не порожній та чи його довжина перевищує 10 символів.  Головний потік (Main) зупиняє своє виконання через join(), очікуючи на завершення перевірок усіма робочими потоками.  Етап 2: Паралельна маршрутизація (Клас ApprovalRoutingTask)Після успішної верифікації запускається окремий потік за допомогою інтерфейсу Runnable для побудови маршруту погодження.  Маршрут будується тільки для тих документів, які успішно пройшли перевірку на Етапі 1.  Для фінансових документів до маршруту динамічно додається бухгалтер ("Ожидает подписи"), а для інших типів документів або фінального кроку — директор ("Ожидает финального утверждения").  🗂️ Структура проєктуПроєкт складається з таких класів та компонентів:Document — модель документа, що містить ID, назву, контент та прапорець статусу верифікації isVerified.  Employee — модель співробітника компанії із зазначенням його імені та посади (ролі).  ApprovalStep — етап маршруту погодження, який пов'язує конкретного співробітника та поточний статус кроку.  DocumentService — сервіс із бізнес-логікою для перевірки вмісту документів та генерації кроків погодження.  DocumentVerificationThread — потік, реалізований через розширення класу Thread, відповідальний за верифікацію.  ApprovalRoutingTask — завдання, реалізоване через інтерфейс Runnable, відповідальне за побудову маршруту.  Main — точка входу, яка ініціалізує дані, керує життєвим циклом потоків та виводить фінальні логи.
